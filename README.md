# Прокат автомобилей

Десктопное приложение для Windows: информационная система «Прокат автомобилей»
(командный проект, Университет «Туран», дисциплина «Проектирование информационных систем»).

Стек: Electron, React, TypeScript, SQLite (better-sqlite3).

## Запуск

```bash
npm install
npm run dev
```

## Установщик для Windows

```bash
npm run dist
```

Готовый `Прокат-автомобилей-Setup-0.1.0.exe` появится в папке `dist/`.
Установщик создаёт ярлык на рабочем столе и запись в меню «Пуск».

## Вход в систему

| Роль | Логин | Пароль |
|---|---|---|
| Руководитель | `boss` | `1234` |
| Менеджер | `manager` | `1234` |
| Кассир | `kassir` | `1234` |
| Специалист по ТО | `to` | `1234` |

Руководитель может загрузить тестовые данные кнопкой в левой панели («Загрузить тестовые данные»).

## Что реализовано (по СРО и ПР)

| Процесс (ПР 3) | Раздел | Роль |
|---|---|---|
| Бронирование: проверка доступности, статусы брони | Бронирования | Менеджер |
| Оформление аренды и выдача: проверка ВУ, договор, доп. услуги, фиксация состояния | Договоры | Менеджер |
| Расчёт и оплата: сценарий ПР 4, оплата аренды и залога, Kaspi QR | Платежи | Кассир |
| Возврат: акт, штрафы, расчёт по залогу, закрытие договора | Возврат, Платежи | Менеджер, кассир |
| Техническое обслуживание: очередь, записи о ТО, смена статуса | Техобслуживание | Специалист по ТО |
| Отчётность: договоры, платежи, загрузка автопарка | Отчёты | Руководитель, менеджер |

Дополнительно: клиенты (физические лица с ИИН, юридические с БИН, история аренд),
автомобили, справочники (11 штук из СРО 10), сотрудники и роли.

Основные правила:
- автомобиль на ТО или недоступный не бронируется и не выдаётся, двойная бронь на пересекающиеся даты запрещена;
- выдача только по подписанному договору клиенту с действующим водительским удостоверением;
- стоимость аренды = дни × (тариф класса + доп. услуги), пересчитывается при продлении;
- принятая сумма не может быть меньше суммы аренды и залога, для Kaspi QR нужен номер операции;
- при возврате штрафы начисляются автоматически (просрочка, возврат без топлива), повреждения вносятся по акту,
  штрафы удерживаются из залога.

## Клиентский режим (СРО 8, сценарии 1–3)

На экране входа кнопка «Я клиент: найти автомобиль» открывает режим без пароля:
поиск свободного автомобиля на даты, заявка на бронирование (бронь создаётся со статусом «Создано», подтверждает менеджер)
просмотр статуса брони по номеру и ИИН и список всех своих бронирований и аренд (по ИИН и телефону).
Служебные данные (VIN, госномер, пробег) клиенту не показываются.

## Данные для страховой компании и бухгалтерии (СРО 3)

- В карточке автомобиля хранятся полисы ОС ГПО ВТС и КАСКО со сроками, история ТО и технического осмотра,
  повреждения и страховые случаи. При приёме автомобиля повреждение можно оформить как страховой случай.
  При оформлении договора система предупреждает, если ОС ГПО автомобиля не указан или истекает раньше окончания аренды.
- Отчёт за период и журнал платежей сохраняются в CSV (открывается в Excel) для руководителя и бухгалтерии.
  Сам бухгалтерский учёт в систему не входит (СРО 2).

## Как применены места, которые документы не уточняют

- **Доступность автомобиля** (СРО 9, шаг 4): в списке только автомобили со статусом «Свободен», без пересекающихся
  броней и не на ТО. «Забронирован» ставится автомобилю, у которого есть бронь на сегодня; бронь на будущие даты
  не меняет статус, её защищает проверка пересечений.
- **Просрочка возврата**: один штраф 10 000 ₸, как в таблице 7 СРО 10 (документ не говорит о начислении за каждые сутки).
- **Закрытие договора** (ПР 3, процесс 4): менеджер составляет акт, кассир выполняет расчёт по штрафам и залогу,
  затем менеджер закрывает договор.
- **Пересчёт стоимости** (СРО 8, сценарий 8): кассир может продлить срок или начислить штраф на вкладке «Принять оплату».
- **Плановое ТО по сроку**: автомобили, у которых последнее ТО было более 180 дней назад, показываются в разделе «Техобслуживание».
- **Дополнительные услуги**: ПР 4 оставляет их перечень на уточнение. В справочнике заданы кресло, GPS и доп. водитель,
  список можно менять в разделе «Справочники».
- **Подтверждение оплаты Kaspi QR**: ПР 4 оставляет способ получения подтверждения на уточнение. Фиксируется номер
  операции из подтверждения банка; прямой интеграции с банком нет (она вне границ ИС по ПР 3).

## Структура

- `db/schema.sql` — схема БД (9 информационных объектов, СРО 10)
- `db/refs.sql` — начальные значения справочников (СРО 10, таблица 7)
- `src/main` — основной процесс Electron: БД, бизнес-логика (`services.ts`), права ролей (`index.ts`), демо-данные
- `src/preload` — безопасный мост между окном и основным процессом
- `src/renderer` — интерфейс на React

База данных хранится в `%APPDATA%\Прокат автомобилей\rental.db`.
